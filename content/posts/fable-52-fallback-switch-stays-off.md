# Fable 5.2 說誤擋少了一半，我那個「被擋就換模型」的開關還是不會打開

臺灣時間 11 月 10 日凌晨，Anthropic 發布了 Claude Fable 5.2 和 Claude Mythos 5.2。[公告](https://www.anthropic.com/claude-fable-and-mythos-5-2)裡我最先找的是安全分類器那一段：Fable 5.2 的資安和生物防護跟 5.1 一樣強，但在 claude.ai、Claude Code 和 Cowork 的早期測試裡，被擋的次數比 Fable 5.1 少了大約 55%，資安類少了大約六成，生物類少了大約四成。同一段也寫了被擋之後會怎樣：資安類改由 Opus 4.8 回答，生物類改由 Opus 5 回答。

我會先找這段，是因為 11 月 1 日我才被擋過。那天我在 T3 Code 裡讓 Opus 5.5 替 FEX 補 x86 偵錯暫存器的支援，FEX 是一個開放原始碼的 x86 模擬器。寫到 wineserver 用 ptrace 設定的偵錯暫存器值，要怎麼生效到遊戲的執行緒時，連續三次被 safeguards 擋下，錯誤訊息最後掛著 `[cyber]`。這行標籤是從哪裡來的，我在 [11 月 2 日那篇](https://b-log.to/ai-analysis/claude-code-game-recreation-rule-not-cyber/)寫過。

## 支援說是誤判

我當天就向 Anthropic 支援回報。11 月 4 日的回信說，三次都是 Opus 5.5 自動安全檢查的誤判。這個檢查刻意設得很寬，讀的也不只是我打的字，模型讀到的記憶、檔案、連接器和網頁結果都算，所以他們也說不出是 session 裡哪一段觸發的。誤判不代表對我的判斷，帳號不會有任何處置。給資安專業人士的 Cyber Verification Program 不適用，我的工作被歸在模擬器和遊戲開發。回信也列了幾個建議：改訊息重送、開一個不帶舊脈絡的新對話，還有檢查「Switch models when a message is flagged」這個設定。

## 這個開關是我刻意關的

這個設定在 Claude Code 的設定檔裡叫 `switchModelsOnFlag`，沒設的話會自動換。Opus 5.5 或 Fable 的請求被標成資安類，Claude Code 會把那個回合改在 Opus 4.8 上重跑，之後整個 session 就留在 Opus 4.8，要自己用 `/model` 切回來。我把它設成 `false`。在能跳出選項的互動 session，它會停下來讓我選；在 T3 這種透過 Agent SDK 跑、跳不出選項的地方，被標的請求就直接以拒絕結束。

我關掉它的原因很簡單：我不要被標的那一步，被默默換給能力比較弱的模型做。支援信自己也寫出了第二個理由：每個模型有各自的安全檢查，換過去不一定能過，另一個模型也擋的話，session 一樣會停下來。開著它，要先付降級的代價，也不保證換得到答案。

11 月 4 日我回信時寫了這兩點，還主動說可以提供專案的 repo，證明我在做什麼。11 月 5 日的回信說已經轉給團隊審查，我問的具體問題都還沒回答。

## 55% 是誰跟誰比

所以看到 Fable 5.2 的公告，我在意的是兩件事。

第一，55% 是 Fable 5.2 跟 Fable 5.1 比。我被擋的是 Opus 5.5，公告沒有說 Opus 5.5 的分類器有沒有一起調。同一份公告也寫，Fable 5.2 的防護會擋下大部分資安相關的工作，真的要做這類事，要去申請 Mythos。我做的是讓遊戲在另一個平台跑起來，支援已經說這不算資安工作，可是分類器讀到 ptrace、讀到寫進另一個程序的暫存器時，不會先問我在做什麼。

第二，被擋之後的路沒有變，資安類還是交給 Opus 4.8。Anthropic 自己建議把最難、最開放的技術工作交給 Fable，而被擋的那一刻，通常也是那段工作最難的時候，接手的卻是比 Opus 5.5 還舊的 Opus 4.8。少擋一半是好事，只是只要還會擋，換過去的那一步就還是同一種降級。

## 開關我不會打開

被擋的時候，我還是照原本的做法：回報、改寫 prompt，先講清楚這是遊戲相容性的工作、開不帶舊脈絡的新 thread，再不行就由我決定改派別的代理。11 月 11 日我已經把 Fable 5.2 用在別的工作上了，像是 Squelch 的音量放大，還有蓬萊的設定選單。那些都不是當初被擋的那一類。它實際能少擋多少，還是要等我把同一類工作交給它才知道。我比較想知道的，是 11 月 5 日那封信說的團隊審查，之後到現在都還沒有新的回覆，最後會不會回答我問的那件事：安全檢查能不能拿到專案層級的脈絡，知道這個 repo 從頭到尾在做什麼。
