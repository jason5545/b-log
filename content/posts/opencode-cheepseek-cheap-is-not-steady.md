# OpenCode 把 DeepSeek 額度從 30 美元加到 100 美元，我有一段時間卻很排斥用它

10 月 31 日凌晨，OpenCode 發了 Operation Cheepseek 第四期：Go 訂閱者的 DeepSeek V4.1 Flash 用量給到 100 美元，這次連每月 40 美元的 Go Plus 也從 160 美元加到 200 美元，Go Teams 從 85 美元加到 105 美元。從 8 月第一期的「10 美元換 30 美元用量」算起，這是第四次往上加，中間是 9 月 25 日的 60 美元（宣布變成常態）和 10 月 12 日的 80 美元。光看這條線，這是一個講到做到的計畫。

可是有一段時間，我很排斥用 OpenCode。額度給得不算少，讓我不想碰的是 Go 上的 DeepSeek 一直算不準：額度先跟著漲價縮水，快取時有時無，速度又一路往下掉。

## 起點是 DeepSeek 漲價

OpenCode 共同創辦人 Dax（@thdxr）今年 4 月在 X 上說過，API token 不是賠錢在賣，這些模型的售價比 GPU 時間成本高很多，視模型而定，毛利有機會到九成。這是他自己的估算，沒有人審計過。四個月後，OpenCode 自己就碰上了低價模型的需求暴增。

8 月 21 日，OpenCode 的 Jay V（@jayair）在 X 上寫了一長篇說明。V4 Flash 8 月 1 日上線，兩週內在 OpenCode 上從每天 3 兆 token 漲到 18 兆；8 月 16 日 DeepSeek 尖峰時段漲價五倍、離峰兩倍半，成長馬上停住，用量掉到高峰的一半以下。他們猜 DeepSeek 自己也接不住六倍的量，所以到處找能照原價供應的業者，但算下來要大約 1,000 張 B300 才撐得住他們的流量。這段期間 Go 上的 DeepSeek Flash 換過好幾家供應商，他自己也承認體驗不好。

漲價當天，OpenCode 公告 Go 的額度跟著新價格調整。Reddit 上馬上有 Go 訂閱者發現，DeepSeek V4 Flash 的月額度從 60 美元變成 15 美元，OpenCode 的維護者後來在 GitHub 上也說，那時 V4 Flash 的上限確實是 15 美元。隔天第一期宣布完成，額度才回到 30 美元。

Jay 那篇裡有一句我覺得是整件事的關鍵：DeepSeek Flash 會這麼便宜，看起來是因為他們有自己的基礎設施，能快取更多 token、放得更久。也就是說，便宜有一大部分靠的是快取命中。換到別家供應商，快取一掉，價格就回到原樣。

## 快取在幾十秒裡來回跳

9 月 21 日，有人在 OpenCode 的 GitHub 開了 [issue #50258](https://github.com/anomalyco/opencode/issues/50258)：Go 上一個叫 frank 的上游，DeepSeek V4.1 Flash 在對話進行中反覆丟掉 prompt cache。他匯出大約 17 小時的請求紀錄，447 筆請求、帳單 1.76 美元，其中大約 57% 是快取掉了之後整段重讀浪費掉的。最怪的是時間點：同一段對話，前一筆才命中 45 萬 token，40 秒後下一筆整段當成未快取重讀，再下一筆又恢復。閒置太久會過期很正常，這裡卻是命中和未命中在幾十秒裡來回跳。

底下的留言也重現了。有人用另一個客戶端、直接送原始 HTTP 請求，內容一模一樣，18 次裡有 8 次完全沒命中。9 月 26 日，開 issue 的那位又貼出自己的帳：同一段對話，前綴一直變長，43 秒後整段 59 萬 token 重讀，那一筆大約 0.089 美元；命中的時候一筆只要 0.002 到 0.003 美元，差了三十到四十五倍。

同一天，Reddit 上也有人用同一個提示詞、同一套 agent 框架，分別走 Go 和 DeepSeek 官方 API 跑程式碼審查。Go 兩次的快取命中率是 74.8% 和 81.1%，官方 API 兩次都是 92.6%；帳面費用 Go 是 0.076 和 0.080 美元，官方是 0.0255 和 0.032 美元。兩邊的上下文長度和總讀取量不一樣，價差不能全算在快取頭上，底下也有人說自己在 Go 上幾乎都有 99%。可是發文的人看到的是，官方 API 一次都沒漏，Go 每隔幾輪就整段沒命中。

我對快取這麼在意，是因為 10 月 15 日才寫過 Claude Code 的閒置壓縮（〈[Claude Code 會在你離開時先壓縮長對話，搶在 prompt cache 過期前](https://b-log.to/ai-analysis/claude-code-idle-compaction-prompt-cache/)〉）。Claude Code 那邊，訂閱方案主對話的快取有一小時，它還會搶在過期前先把長對話壓短。DeepSeek 官方 API 沒有保證時間，文件寫的是盡力而為，不再使用的快取通常幾小時到幾天內清掉。兩邊都會過期，但至少有一條看得到的線。Go 那時候少的就是這條線：40 秒就沒命中，怎麼看都不是過期。issue 裡的人懷疑是請求被送到不同的上游，各自的快取不共用，可是官方一直沒有確認，使用者自己也算不出來快取什麼時候會掉。OpenCode 2 後來加了一個暖機功能，閒置四分鐘就送一次請求幫你把快取留住，但它預設是關的，送出去的每一次也都是真的請求，要照樣計費。

速度也是同一種狀況。9 月 24 日的 [issue #51010](https://github.com/anomalyco/opencode/issues/51010) 量到 Go 上的 V4.1 Flash 輸出中位數每秒 184 token，DeepSeek 自己的 API 是 233，另一家 Command Code 是 271；同一份紀錄裡，Go 上線那週還有 249 到 266。10 月 15 日同一位再量一次，掉到 119，同一台電腦走另外兩條路都沒變慢。

## 10 月下旬，兩則 issue 都關了

10 月 21 日，OpenCode 的維護者把這兩則 issue 都關掉。快取那則的說法是：之後 Go 對 DeepSeek 的路由和快取改了很多，問題很可能已經修好，再遇到就開新的 issue，附上時間和請求 ID，額度因此被吃掉的可以寫信要求處理。速度那則則說，這是模型透過 Go 提供時的表現，不是 OpenCode 程式的問題，他們會轉給上游供應商。關掉之後，速度那則下面 10 月 26 日還有人說降到每秒 40 token 以下，10 月 28 日也有人貼了自己兩週、一萬四千多步的等待時間量測。

Dax 10 月底到 11 月初的幾則貼文也看得出供應還沒穩。10 月 27 日他說又在找 GB300 機櫃，誰最快交貨就跟誰買。11 月 1 日凌晨他說，偶爾有人回報 Go 上的 DeepSeek 變笨，他拿找得到的基準測試把各種設定重跑一次，結果都在同一個範圍，不過也找到兩個低流量設定有問題，會直接拿掉。同一個晚上他回網友時也講明，第一條路由是他們自己的 GPU 叢集，可是撐不住全部的尖峰流量，有些請求會被轉去 DeepSeek 官方 API；速度慢是因為硬體不夠，要等找到更多機器才會改善。

## 額度兌現了，帳還是算不準

所以 Cheepseek 我會說有兌現：30、60、80、100，每一期都真的給了，10 月 15 日還多了一條免費的 V4.1 Flash 路由。不過免費那條的上下文只有 200K，付費的 Go 是 1M，文件也寫著限時。每一次加碼也不全是 OpenCode 找到了便宜的 GPU，9 月 10 日 DeepSeek 發了 V4.1 Flash，官方 API 本身就降價了。

可是額度加到 100 美元，和那 100 美元能不能穩定換成一樣多的工作，是兩件事。快取掉一次，那一筆就貴了三十到四十五倍；速度掉一半，同樣的任務就要多等一倍的時間。Dax 那句九成毛利，我沒辦法說他錯，沒有 OpenCode 和供應商的成本帳，誰都算不出來。可是這半年擺在眼前的是，單位 GPU 算力便宜，和用低價長期穩定供應大規模的 AI 寫程式推論，中間還差了一大段。供應商換來換去、機器還在找，我拿到的就不是一個算得準的價格。

要看的是每個做完的任務實際花了多少，不是公告上那個額度數字。9 月底那時，我的語音輸入規則助手預設模型還是 Go 上的 DeepSeek V4.1 Flash；最近我又開始透過 T3，把一些別的工作交給 Go 上的 DeepSeek。第四期的 100 美元能換到多少個做完的任務，要等我自己的帳單說了才算。
