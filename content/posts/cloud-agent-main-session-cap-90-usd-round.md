# 我只管主 session 不要爆掉，雲端 agent 那一輪花了 90 美元

雲端額度一開始是 250 美元。階段 1、2 兩輪花了 83，剩 167。階段 3 跑完，剩 77。

階段 3 一輪就花了 90 美元。

## 這筆錢只能在雲端用

Anthropic 送了 250 美元，只能用在 Claude Code 的雲端。要不是只限雲端，我才不會這樣用，我就用到我的主力了。可是擺著也是浪費，所以我拿來學怎麼管理雲端 agent 的 context window 和用量。

雲端 agent 有一個問題：擺著，我就去睡覺了，或去忙別的。它在跑的時候，沒有人看著。

題目挑了一個卡牌 roguelike，像 Slay the Spire、Monster Train 那種。那兩款都是美式畫風，太醜了，所以我只說要日系。名字叫式札 Shikifuda，網頁遊戲，手機桌機都能玩，圖全部由 Claude 用程式畫。

這個 project 我是完全放手的。每個階段是一個獨立的雲端 session，做完自己開 PR、自己 merge、更新交接檔，再叫我開下一個。拆成這樣，是怕 context window 失控。我自己不會做太多 steering。

額度用完就回到訂閱，反正是實驗。做得不錯的話，我會接著把它做完。希望做出來是可以玩的，好玩的。

後來我跟 Claude 說，這其實有點像一場大型的雲端 [Build Day](https://b-log.to/tech-development/first-hackathon-code-done-in-37-minutes/)，只是沒有時間限制、沒有排名，自己玩得開心就好。它回我：沒有時間限制，不代表沒有限制，這次的時鐘是錢。

## 我先把一個數字看錯了

Claude Code 的系統提示裡有一行「tokens left」，開場是 15,000,000。我一直以為那是還剩多少 context window。

請 Claude 查了才知道不是。每傳一則新訊息，這個數字就重設回 15,000,000，它是這一輪的工作預算。Opus 5.5 的 context window 是 1M。

我原本的規則是：盡量用子代理，主 session 用到 25% 就停，叫我開下一段。照 15,000,000 算，25% 是 375 萬，早就超過 context 的上限。後來改成主 session 用掉 25 萬就交接。

子代理我不管。它們要怎麼用，我無所謂，主 session 不要爆掉就好。讓雲端的 agent 自己把工作做最佳化分配。

## 它真的照做了

階段 3 開工，行為完全變了。

以前主 session 自己都還會做一大堆。這一輪一開始就派子代理，功能派了五個，連整合也另外派一個代理處理。主 session 只用了約 14 萬 token，規則守得很好。

然後是 90 美元、2 小時 40 分。前兩輪是主 session 自己做，平均一輪大約 41。

我請 Claude 分析。它的解釋是這樣：同一個 session 越做越長，每一步大多是在重讀已經在快取裡的東西，Opus 5.5 讀快取每百萬 token 0.20 美元，很便宜。每開一個新的子代理，系統提示、規則檔、讀的每個檔案都要重新寫進快取，每百萬 token 5 到 8 美元，貴 25 倍以上。幾個子代理讀同一批程式，就付幾次。

我管的是主 session 會不會爆，沒有管錢。它也就只省主 session，把工作搬到最貴的地方去做。

還有自動接力。我設了一個 routine，標題有「[接力]」的 PR 一 merge 就自動開下一輪，燃料先給 3 輪。階段 3 的 PR 在 18:10:21 merge，18:10:23 下一輪就開工了，照同一套分配。我把它停掉的時候，它才跑了六分鐘。

那時燃料還剩兩輪，額度剩 77。照一輪 90 的花法，那天如果我是去睡覺，第一輪接力就會把額度燒完，接著用我的訂閱。

## 改成一個 Sonnet 做到底

我在 Codex 那邊有一套分工：Astra 規劃、Luna 實作、Astra 驗收。給本機模型的指示也有一套寫法。我問 Claude，Sonnet 能不能照這套來，甚至從頭到尾一次做完，會不會比較好。

新規則是：Opus 讀交接檔、寫完整的實作計畫；交給一個 Sonnet 5 子代理從頭做到尾，不拆成平行，要補改就接回同一個；Opus 自己看 diff、重跑測試、看截圖驗收。

我另外只加了一條：畫圖給 Opus 畫，主代理自己完成。

階段 4 前半做完，額度剩 46 美元。這一輪 31 美元，大約一個半小時，目前單輪最便宜。

## 便宜，是因為做得少

Claude 把各輪的量算了出來，是新增的程式和測試行數，扣掉 lock 檔和文件：

| 輪 | 做法 | 新增行數 | 花費（美元） | 每千行 |
|---|---|---|---|---|
| 1 | 主 session 自己做，美術外包 | 約 9,900 | 約 41 | 約 4 |
| 2 | 同上 | 約 9,000 | 約 41 | 約 5 |
| 3 | 全部派子代理 | 約 8,600 | 90 | 約 10 |
| 4 前半 | Opus 規劃＋畫圖，Sonnet 實作 | 約 2,000 | 31 | 約 15 |

第 1、2 輪共 83 美元，平均算。

行數是很粗的尺。後面幾輪是在改既有的程式，要調平衡，測試也越跑越久，本來就比從零開始寫貴。但差到三四倍，不能全推給這些。這輪便宜，主要是範圍砍小了：階段 4 拆成兩半，這輪只做前半。

原因跟上一輪是同一個。Opus 跟 Sonnet 讀快取一樣價，都是每百萬 token 0.20 美元，Sonnet 只有輸出和寫快取便宜一半。可是 Opus 要寫出計畫，得先把相關的程式讀一遍，Sonnet 接手又讀一遍。這一輪 Opus 用了 41 萬 token，畫圖只佔 12 萬。

我在 Codex 那邊實測過，子代理沒有比較省用量。到了 Claude 的雲端，目前看起來也一樣。

## 這些生物是什麼，我都不知道

做出來的東西，我拉回本機跑。一局變成兩幕：打完第一幕的頭目，穿過山門，再往上爬十二層，最後一隻叫鵺。

![式札第二幕的頭目戰：左邊是陰陽師，右邊是站在黑雲上的鵺，紅臉、黑身、蛇尾，頭上兩道閃電](/content/img/2026/cloud-agent-main-session-cap-90-usd-round-nue.webp)

說實話，這些生物是什麼，我都不知道。一開始討論的只有「日系」這個主題，結果 Claude 就選了這條線：卡面走浮世繪和花札，敵人走剪紙影繪。

我本來想做的是動漫風。Claude 後來跟我說，用程式畫做不出來，這點我可以認同。

做成這樣也不錯，挺特別的。至少比原本參考的那兩款美式畫風好很多。

Claude 看的時候抓到一個小 bug：手機橫放打鵺，頭上的意圖徽章會被切掉一截。這個我沒交給雲端，請它開一個本機的 chip 去修。

雲端還剩 46 美元。我還要留一些自己用。
