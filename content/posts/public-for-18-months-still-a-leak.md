# 公開 repo 裡放了一年半的文件，Claude Code 還是說那是外流

11 月 14 日，我跟 Claude Code（Opus 5.5）的意見不一樣。openfsd 這個專案裡有一份 docs/vatsim-auth.md，它不願意碰，理由是這是外流的東西。

先說這份文件是什麼。[openfsd](https://github.com/renorris/openfsd) 是 GitHub 上的專案，MIT 授權，可以自己架的多人飛行模擬伺服器，用的是 VATSIM 的 FSD 協定。VATSIM 就是有真人航管的那個線上飛行網路。docs/vatsim-auth.md 寫的是 VATSIM 怎麼驗證它核准的客戶端，文件自己也把 "verify" 加了引號，稱那是一套混淆機制。最後附了一張表，列出九個客戶端的編號和私鑰。這篇不會貼其中任何一個編號或私鑰，也不會寫它們怎麼用。我最近在做一個連 VATSIM 的東西，這篇不談它，只談它帶出來的問題：一份在公開 repo 放了這麼久的東西，還算外流嗎？

時間我要先對清楚。這份文件在 openfsd 2025 年 5 月 13 日的第一個 commit 就有了，到現在一年半。表裡最晚補上的一列是 2026 年 6 月 16 日，離現在也有五個月。11 月 14 日查的時候，它還在 main 上，repo 也有 24 個 fork。

我理解的外流，指的是最初洩出去的那一下，那是一次事件。就算它最早真的是外流出來的，發生過就是發生過了。後來它躺在公開 repo 裡，任何人點開網址就看得到，拿到它不需要任何不正當的手段，它現在的狀態就是公開資訊。

我在 agents.md 裡早就寫清楚了：所有專案只能參考公開 repo 的東西。這條我也確實做到，openfsd 是公開 repo，這份文件就放在裡面。結果 Claude Code 給的理由還是外流，不願意碰這份文件。

另一件事我要分開講。談論、研究、解釋一份公開文件的機制，我覺得沒有問題。需要小心的是拿私鑰去冒充正牌客戶端，連上官方網路。那是使用行為，是另一個問題，這篇不展開。我看到的是 Claude Code 把這兩件事放在同一個標籤底下，用「外流」擋掉的是讀文件，真正該小心的卻是怎麼使用。

同一份文件，我寫在 agents.md 的規則問的是現在從哪裡拿得到，Claude Code 問的是它最早怎麼出來的。
