# 訂閱補貼沒有收回，它長出了圍籬

三月我寫過一篇〈AI 服務的 SLA 問題〉，結尾是：補貼空間正在被一點一點收回。

半年後，這句話要修正。補貼沒有收回，它變得更大了——只是每一格旁邊，都長出了圍籬。

## 同一筆 $200，他現在算成 $8,000

Theo 十月初在節目上，把現在的局面講成「訂閱套利」。他的算法：$200 的 Claude 訂閱，按 API 牌價換算大約值 $8,000 的推理量；$200 的 Codex 值 $12,000，把 reset 的節奏也吃滿是 $24,000。補貼幅度，他算 95–98%。

三月我引過他的舊數字，同一筆 $200 是 $4,000。半年，翻了一倍。

他對用法的結論很直白：能走訂閱的任務就不要走 API——「那一塊錢，有八、九毛是丟掉的」。他甚至說，如果廠商哪天把補貼用量限在離峰時段，他願意為了保住補貼，調整自己的睡覺時間。

## 帳面越給越大，控制越收越細

同一段時間，廠商的手也沒停。

OpenAI 十月把 $200 Codex 方案的價值砍掉將近一半，同時開了 $500 一層；八月起 reset 變成可以加購的東西；九月再把重度使用者的額度大幅收緊。

Anthropic 的線曲折一點：五月把 5 小時限制永久加倍，把三月底才上線的尖峰降速整條拿掉；九月臨時加量到期，換成比原始基準多 25% 的永久值——跟臨時加量時相比，等於收回了一成七。

我的讀法：面額往大的方向走，控制往細的方向走。補貼從吃到飽，變成有條件的給。

## 我的 $200，只燒得掉 $100

十月十三日，下午五點到晚上八點，我拿 Opus 5.5 跑互動式 Claude Code。手上兩筆額度：一筆是九月 Build Day 拿到的 $100，一筆是這個月官方開始送的每月 API credit $100，帳面合計 $200。

三小時，燒掉 $100，然後我被擋住了。剩下那 $100，還好好列在帳上。

查了才確定：官方把互動式 Claude Code 明文排除在每月 API credit 之外。涵蓋範圍寫得很清楚——Claude API、批次 API、Playground、託管代理程式、Agent SDK——互動式 session 不在名單裡。就算額度還在，跑 Claude Code session 只會拿到一句「Credit balance too low · Add funds」。

我燒掉的是另一條。剩下那條不是餘額不足，是它設計上不吃我這種用法。

$100，三小時。這是 Opus 5.5 牌價跑出來的真實速度。

## 圍籬才是現在的本體

Theo 的做法是繞著圍籬走：多代理並行、改睡覺時間跑 agent、把 reset 的節奏算進排程。

我務實一點。這晚不是白撞的——付了三個小時學到的是：補貼的形狀不是金額，是圍籬。每一筆都綁著條件，哪顆模型、哪個介面、哪個時段、哪層方案。看起來是 $200，能不能動用，取決於你的用法落在哪一格裡。

剩下那條 $100 還是用得到，換成 `claude -p` 或 API 的用法就好。它不是壞掉，只是要我換一種方式去用它。

## 最後

三月我說補貼在收回。現在修正：它沒有收回，它換了姿勢——面額更大，圍籬更細。

Theo 押的下一個圍籬是離峰時段。我猜他會比大多數人先適應。
